一、采集并保存数据（trial 级别）

python -m epstudiosdk.realtime_record_trials --config .\data\config.ini --sfreq 992

按键说明：

1/2/3/4 选择当前标签：up/down/left/right（内部 label_id=0/1/2/3）

Space 开始/结束一个 trial（会保存一个 trial_XXXX_labelY_*.npz）

Esc 退出（会停采集并收尾保存）

建议采集节奏：每个动作至少 20–30 个 trial，每个 trial 1–2 秒，中间放松 1–2 秒。总量上来以后模型才稳。

>python -m epstudiosdk.realtime_decode_udp --config .\data\config.ini --ckpt .\epstudiosdk\cnn_4actions_finetuned_0313zly.pth --sfreq 1000 --ip 127.0.0.1 --port_udp 5005

打开浏览器游戏，点一下游戏窗口让它获得焦点；此时收到 UDP 的 event start 就会触发一次 w/s/a/d（或你改成方向键也行）。

注意两条最容易踩坑的点：

采样率必须一致：你保存时 --sfreq、切窗时隐含的 sfreq、在线推理时 --sfreq 要一致，否则窗口点数和特征尺度都会错。

通道顺序必须一致：训练用的通道顺序 = 在线推理堆叠 [L,C] 的顺序。你当前 realtime_waveform.py 是按 channels 列表遍历

realtime_waveform

，训练/在线都要保持同一顺序。

补充说明：你原来的离线回放脚本 emg_replay_udp.py 已经实现了“滑窗预测→事件去抖（start/hold/end）”的思路

emg_replay_udp

，在线版也是同一套逻辑；游戏控制建议只用 event start 做一次 tap，避免抖动连发。
